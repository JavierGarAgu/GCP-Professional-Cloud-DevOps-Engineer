# Q86 - Export Cloud Logging Logs to Pub/Sub Using Terraform

## Overview

This lab demonstrates how to export Google Cloud logs from **Cloud Logging** to **Pub/Sub** using Terraform.

The architecture simulates a common security monitoring scenario where Google Cloud services generate logs, Cloud Logging collects them, and a Logging Sink exports them to a Pub/Sub topic. A consumer can then process the messages in near real time for alerting, monitoring, or integration with external security platforms.

This solution is similar to the architecture used in Google Cloud Professional Cloud DevOps Engineer exam questions.

# main.tf Explanation

## Provider

The provider connects Terraform to the Google Cloud project.

```text
Project:
devops-cert-labs-v3

Region:
europe-west1
```

---

## Enable Required APIs

Terraform enables the services required for the lab.

```text
logging.googleapis.com

pubsub.googleapis.com

compute.googleapis.com
```

Without these APIs, the resources cannot be created.

---

## Pub/Sub Topic

A Pub/Sub topic named:

```text
security-logs-topic
```

is created.

The Logging Sink publishes every exported log into this topic.

---

## Pub/Sub Subscription

Terraform creates a subscription:

```text
security-logs-sub
```

The subscription allows consumers to receive the log messages stored inside the topic.

---

## Logging Project Sink

Terraform creates a Logging Sink.

```text
Cloud Logging
        │
        ▼
Project Sink
        │
        ▼
Pub/Sub Topic
```

The destination is the Pub/Sub topic created earlier.

Whenever Cloud Logging receives a matching log entry, it immediately forwards it to Pub/Sub.

---

## IAM Configuration

Each Logging Sink automatically creates a service account.

Terraform grants that account the following role:

```text
roles/pubsub.publisher
```

Without this permission, Cloud Logging cannot publish messages to the Pub/Sub topic.

Terraform automatically retrieves the generated service account by using:

```text
writer_identity
```

No manual configuration is required.

---

## Virtual Machine

A small Debian virtual machine is deployed.

The startup script continuously writes log entries using the Linux logger command.

```text
logger "Generating Cloud Logging entry"
```

These logs are collected by Cloud Logging and exported through the Logging Sink.

# Why Use Pub/Sub?

A Logging Bucket stores logs for later analysis.

A Pub/Sub topic delivers logs immediately to subscribers.

This makes Pub/Sub the preferred destination for:

* Near real-time monitoring
* Security alerting
* SIEM integration
* Automated incident response
* Event-driven architectures

# Relation to the Certification Exam

A common Professional Cloud DevOps Engineer question asks how to centralize logs generated by Google Cloud services while allowing near real-time analysis.

The recommended solution is:

```text
Cloud Logging
        │
        ▼
Aggregated Logging Sink
        │
        ▼
Pub/Sub
```

In this lab, a **Project Sink** is used because it can be deployed inside a single project.

In production environments, the same architecture is usually implemented with a **Folder Aggregated Sink** (`include_children = true`) so that logs from multiple projects are exported to a central Pub/Sub topic.
